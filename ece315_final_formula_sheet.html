RTOS Rules That Matter

  • Single-core FreeRTOS default: fixed-priority, preemptive scheduling.
  • The highest-priority ready task runs.
  • Equal-priority ready tasks can round-robin on the tick if time slicing is enabled.
  • Blocked tasks use no CPU time.
  • ISR work should be short; wake a task for the longer processing.
  • Event-driven beats busy-waiting when activity is irregular.
  • For periodic tasks, use timer-driven or absolute-period release; repeated relative delays accumulate drift/jitter.
Task states: Running | Ready | Blocked | Suspended
Tick interrupt = scheduler heartbeat for delays/time slicing/timeouts

RTOS Object Picker

Object Use It For Remember
Queue Pass data between tasks Data + sync together
Binary semaphore Event signaling, ISR -> task No owner, no priority inheritance
Counting semaphore Count repeated events/resources Good when events can pile up
Mutex Protect shared bus/resource Has owner + priority inheritance

Critical section Tiny atomic code region Never block inside it

Priority Inversion

Classic pattern: a low-priority task holds a mutex needed by a high-priority task. The high task blocks, then a medium task runs and delays the low task from releasing the mutex.

Fix: use a mutex so the low task temporarily inherits higher priority. A plain semaphore does not give ownership or priority inheritance.
  • Keep mutex hold time short.
  • Do not do long I/O inside a protected region unless absolutely required.
  • Protect data with mutexes; signal events with semaphores/notifications.

Interface Quick Pick

Bus Pick When Gotcha
UART Point-to-point async stream, debug, PC link No clock; framing depends on baud match
SPI Fast local peripheral link Usually one CS per slave, mode must match
I2C Many low/medium-speed devices, low pin count Open-drain + pull-ups + ACK/NACK
RS-485 Noisy long-distance multidrop Differential, often half-duplex
CAN Robust multi-node control bus Lower numeric ID wins arbitration
Ethernet Need standard network/LAN Highest protocol complexity here

UART / Serial Math

t_frame ~= (start + data + parity + stop) / baud
8N1 => 10 bits/byte => bytes/s ~= baud / 10
drift ~= elapsed_time * ppm / 106

For two free-running clocks, worst-case relative drift usually uses the sum of the absolute ppm errors.

Flag Meaning
RXC Receive complete
UDRE Transmit data register empty
TXC Whole frame fully sent
FE / DOR / UPE Framing / overrun / parity error
Non-intuitive one: UDRE means you can load the next byte; TXC means the stop bit of the previous frame has finished.

SPI / I2C / CAN Pressure Notes

  • SPI: synchronous, usually full duplex, fast, local, common for ADC/DAC/display/sensors.
  • I2C: addressed shared bus, fewer wires, lower speed, START/STOP/ACK/NACK matter.
  • RS-485: differential + noise-robust + multidrop.
  • CAN: robust arbitration + messaging; strong for distributed control.
Short answer defaults:
SPI = local + fast + dedicated chip select acceptable.
I2C = shared addressed bus + low wire count.
UART = simple async point-to-point or debug console.

MMIO, IRQs, DMA, Timers, PWM

Bring-up order, interrupt hygiene, and CPU-offload logic

This side is the "do not blank on implementation order" page: pin mux, event chain, edge vs level, DMA pacing, timer math, and PWM relations.

Memory-Mapped I/O

Peripheral registers live at fixed addresses in the CPU address space, so the processor configures hardware with normal loads/stores.

Bring-up: reset/clock -> control regs -> GPIO alternate function -> enable -> IRQ/DMA
  • RP2040 reminders: GPIO alt functions, UART/SPI/I2C, ADC, PWM, timer, DMA, subsystem resets.
  • Atomic set/clear/xor register aliases are safer than read-modify-write when hardware is live.

volatile, Atomic, Critical Section

  • volatile is for hardware registers and flags shared with ISRs.
  • volatile forces real reads/writes; it does not make access atomic.
  • Use atomic registers, a critical section, or a mutex when multiple contexts can modify the same resource.
  • Critical sections are for very short regions only; do not call blocking APIs inside them.
Memory visibility problem and mutual exclusion problem are not the same thing. volatile helps visibility, not safe sharing by itself.

Interrupt Rules

  • Clear the interrupt source.
  • Move minimal data if needed.
  • Wake or notify a task.
  • Do the heavier work in task context.
  • Use only ISR-safe APIs from an ISR.
Trigger Type Remember
Edge One transition triggers it
Level Remains active while condition stays true; clear/remove cause or it retriggers

Polling vs Interrupt vs DMA

Method Best For Main Cost
Polling Slow/simple/periodic checks CPU wasted + latency = poll period
Interrupt Async moderate-rate events Too many interrupts can overload CPU
DMA Repetitive high-rate transfers More setup + buffering discipline
Good exam line: "Use DMA with block transfers so the CPU handles only block-complete interrupts instead of every sample/byte."

Event Chains

Hardware-to-hardware triggering removes software jitter and lowers CPU load.

timer -> ADC start -> ADC FIFO -> DMA -> RAM buffer -> task processes completed block
  • Use timers for periodic release instead of busy loops.
  • Use sensor data-ready or DMA-complete IRQs for event-driven tasks.

DMA Essentials

  • Best for ADC samples to RAM, UART RX/TX buffers, SPI bursts, waveform tables.
  • DREQ/TREQ pacing means the peripheral says when the next transfer is safe.
  • Double buffering: DMA fills A while CPU processes B, then swap.
block_interrupt_rate ~= sample_rate / block_size
block_time = block_size / sample_rate
Bigger blocks reduce interrupt load but increase latency. This tradeoff shows up in almost every ADC/DMA design answer.

DMA Failure Modes

Problem Mitigation
Buffer overrun Larger buffers, double buffering, lower rate
CPU cannot keep up with blocks Increase block size, reduce processing, lower rate
DMA and software both touch FIFO/resource Clear ownership and sequencing
Too many completion IRQs Block transfers, not per-sample handling

Timer Math

T = 1 / f
counts ~= delta_t * f_clk / prescaler
delta_t ~= counts * prescaler / f_clk
  • Timers are for periodic tasks, timeouts, pulse measurement, and alarm IRQs.
  • Use alarms/timebases to avoid software delay loops.

PWM Relations

duty = T_on / T
V_avg ~= duty * V_high
f_pwm ~= f_clk / (divider * (TOP + 1))
duty ~= compare / (TOP + 1)
  • PWM approximates analog only after filtering or when the load averages it naturally.
  • Useful for LED dimming, motor speed, and DAC-like output.

ADC, DAC, Sampling, Sensor Interfacing

Core formulas, aliasing traps, data-rate math, and analog front-end reminders

This is the side to lean on for Q20-style reasoning: conversion math, anti-aliasing, DMA-friendly acquisition, and how to talk about real sensors in one compact answer.

ADC Core Formulas

levels = 2N
LSB ~= Vref / 2N
quantization error ~= +/- 0.5 LSB
code ~= (Vin / Vref) * (2N - 1)
Vin ~= code * Vref / (2N - 1)

Common course convention: use Vref / 2^N for LSB size, but use (2^N - 1) when mapping codes to full-scale values.

12-Bit Example

For a 12-bit ADC with Vref = 3.3 V:

levels = 4096
LSB = 3.3 / 4096 = 0.0008057 V = 0.806 mV/bit
Vin = 1.65 V -> code ~= (1.65 / 3.3) * 4095 ~= 2048
  • RP2040 ADC reminders: 12-bit SAR, FIFO, DMA-friendly.
  • Great pattern: timer-triggered sampling into FIFO, DMA blocks into RAM.

Sampling and Nyquist

f_s >= 2 * f_max
T_s = 1 / f_s

Practical designs often sample higher than Nyquist so waveform capture is cleaner and analog filtering is easier.

Example: if f_max = 1 kHz, minimum f_s = 2 kS/s; practical might be 10 kS/s

Aliasing

Aliasing happens when sampling is too slow. High-frequency content folds into false lower-frequency content.

One folded-frequency form: f_alias = |f_in - k f_s| for the nearest integer k
  • Once aliased, the original information is lost.
  • Prevent it with an analog low-pass anti-alias filter before the ADC input.
  • Oversampling gives filter transition band room.
Exam phrase: "An anti-alias filter is needed so out-of-band content does not fold into the sampled band."

Data-Rate and Buffer Math

bytes/s = f_s * channels * bytes_per_sample
buffer_time = samples_per_buffer / f_s
buffer_IRQ_rate ~= f_s / samples_per_buffer

Example: 2 channels at 10 kS/s, stored as 16-bit values:

bytes/s = 10,000 * 2 * 2 = 40,000 B/s

Multi-channel sampling often needs de-interleaving after DMA if the ADC cycles through channels.

DAC and PWM Output

Vout ~= code * Vref / (2N - 1)

Example: 12-bit DAC, Vref = 3.3 V, code = 2048 gives about 1.65 V.

Method Remember
DAC Direct analog output, but watch settling time, reference accuracy, and loading
PWM Analog-like after averaging/filtering; still has ripple and switching content

Analog Front-End Checklist

  • Amplification
  • Attenuation
  • Offset/level shift
  • Low-pass filtering
  • Buffering / impedance matching
  • Input protection
  • Match sensor range to ADC range
High resolution does not imply high accuracy. Reference accuracy, noise, and front-end errors all matter.

Motion Control, CPU Budget, Failure Modes

Stepper math, A4988 reminders, actuator comparisons, and quick reusable wording

This side is tuned for Q21-style design reasoning: pulse-rate math, driver selection, when open-loop is enough, and what to say about bottlenecks and mitigations.

Stepper Motor Formulas

step_angle = 360 deg / steps_per_rev
steps_per_rev = 360 deg / step_angle
effective_steps_per_rev = full_steps * microstep_factor
step_frequency = effective_steps_per_rev * RPM / 60
position_deg = (steps / steps_per_rev) * 360
  • 1.8 deg stepper => 200 full steps/rev.
  • Microstepping improves smoothness/resolution, but torque per microstep is lower.

Stepper Example

1.8 deg motor, 1/16 microstepping, 65 RPM:

effective_steps_per_rev = 200 * 16 = 3200
step_frequency = 3200 * 65 / 60 = 3466.7 steps/s
4 motors -> about 13.9 ksteps/s total pulse demand
High step rates argue for timers, PWM, DMA, PIO, or other hardware-assisted pulse generation, not naive software polling.

A4988 Reminders

  • STEP pulse rate sets speed; DIR selects direction.
  • MS1/MS2/MS3 select microstep resolution.
  • Normal control is pin-based STEP/DIR, not an I2C/SPI-style bus peripheral.
  • STEP minimum high ~= 1 us; minimum low ~= 1 us.
  • nENABLE, nRESET, nSLEEP can often be shared across motors if system behavior allows it.
MS1 MS2 MS3 Mode
L L L Full step
H L L Half step
L H L Quarter step
H H L Eighth step
H H H Sixteenth step

Open-Loop vs Closed-Loop

  • Open-loop: simple, cheap, often fine when load is predictable.
  • Closed-loop: uses encoder/feedback, better robustness and confidence in position.
  • Tradeoff: more sensing, more computation, more complexity.
Good wording: "Closed-loop control improves confidence in position and can correct lost motion, but open-loop may be sufficient if the load is predictable and simplicity is preferred."

CPU Budget Reasoning

CPU_load ~= C_irq * f_irq + C_block * f_block + C_ctrl * f_ctrl

C terms are worst-case service times; f terms are event rates.

  • Keep headroom for burst load, retries, and timing jitter.
  • Larger DMA blocks reduce CPU load but increase latency.
  • If CPU load is too high: reduce interrupt rate, increase block size, use DMA, lower sample/control rate, simplify processing.
Course-ready line: "The design is feasible if the CPU remains at least about 70% available under worst-case conditions."

Failure Modes to Name Fast

Failure Mode Mitigation
Missed interrupts Short ISR, lower event rate, use DMA
DMA/buffer overrun Double buffering, larger blocks, lower rate
Aliasing Higher sample rate + analog anti-alias filter
Race condition Mutex/queue/critical section as appropriate
Pulse jitter / timing error Hardware-timed pulses, not software delays
Insufficient torque at speed Lower speed/accel, better driver, use feedback

Reusable Short Answer Phrases

  • "This peripheral is memory-mapped, so the CPU configures it by writing control registers at fixed addresses."
  • "DMA is preferred because the transfer is repetitive and high-rate; the CPU only handles block-complete interrupts."
  • "SPI is appropriate because the peripheral is local, speed matters, and a dedicated chip-select is acceptable."
  • "I2C is appropriate because the design benefits from a shared addressed bus and low wire count."
  • "An anti-aliasing filter is needed so out-of-band content does not fold into the sampled signal."
  • "Open-loop stepper control is simpler but cannot detect missed steps without feedback."
