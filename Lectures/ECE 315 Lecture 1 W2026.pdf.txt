ECE 315 Learning Objectives
1. Explain the architecture and operation of embedded systems, including microcontrollers, peripherals, and I/O subsystems.
2. Differentiate between analog and digital interfacing methods used in embedded systems.
3. Design and implement digital input/output interfaces for sensors, actuators, and external devices.
4. Apply analog interfacing techniques using ADCs (Analog-to-Digital Converters) and DACs (Digital-to-Analog Converters).
5. Develop firmware to communicate with peripherals via standard protocols such as I²C, SPI, and UART.
20
20

ECE 315 Learning Objectives ­ cont'd
6. Use interrupt-driven programming and timers to manage real-time tasks in embedded applications.
7. Implement serial and parallel data communication between embedded devices and external systems.
8. Integrate sensors and actuators into a functional embedded system, handling signal conditioning and calibration.
9. Employ embedded software tools (e.g., IDEs, debuggers, compilers) to program and test hardware interfaces.
10.Demonstrate the ability to interface embedded systems with external devices such as displays, motors, and wireless modules.
21
21

ECE 315 Learning Objectives ­ cont'd
11.Gain experience with the use of the C programming language, including the use of pointers, to implement a real-time embedded system.
12.Become familiar with DC and stepper motor technology and be familiar with different ways of generating the digital signals that are required to control stepper motors.
13.Analyze and troubleshoot hardware­software integration issues using oscilloscopes, logic analyzers, and diagnostic tools.
14.Design, build, and document a embedded interfacing project that demonstrates real-world data acquisition or control.

ECE 315 Learning Objectives - Summary
· You should be comfortable thinking in terms low level operations with bits ­ getting them and outputting them
· You should have a good understanding of how a microprocessor/controller can be used to acquire real-world information, process it, and use the results to control other devices
· Should always ask what are the real timing requirements
· Is some other machine relying on this? Probably hard real-time · Is a human relying on this? Probably soft real-time · Is this a safety-critical situation? Most definitely hard real-time!!!
· This will help you understand mechatronic and robotic systems
