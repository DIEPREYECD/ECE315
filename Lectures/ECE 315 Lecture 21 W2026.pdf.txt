Memory-mapped Systems

· Make a file appear to be all in virtual memory · Read-only (RO) or Read-Write (RW)
· Anonymous Mapping
· Supports extended "RAM" storage for operating systems · Makes the system appear to have more RAM that it physically has

Memory Mapping
· Modern computers (mainframes, laptops, desktops, etc.) have a virtual memory that is not physically present
· Consider an N-bit processor
· If N=32, then 232-1 = 4GB, which could easily be all RAM · If N=64, then 264-1 = 17,179,869,164GB; no way that
can be all RAM
· Instead, we can extend the available RAM "virtually" with another form of storage, often a disk (HD, SSD)
· A mmap() function or device will "map" the extended space to bytes on the secondary (disk) storage

File Memory Mapping
File Mapping ­ file is allocated from virtual memory · Can be set up as read-only (RO) or read-write (RW) · Writing to RO will cause an operating system error
· A good programmer will handle it gracefully; no crash
· The mapped storage is handled as a file
· All the usual file operations can be done with it · Logically, starts at an address and is contiguous · The physical storage it's mapped onto may or may not be
contiguous · The memory mapping function, mmap(), manages that
abstraction

Aside ­ Virtual Memory

· Gives the appearance of a large block of memory even if the physical RAM is much smaller
· Main idea
· Divide the process memory into contiguous "pages" of fixed size
· They are in "virtual memory"
· Store the pages on disk and when the program needs the memory mapped to a specific page, fetch it and place in RAM

What does this have to do with interfacing?
· How the computer bus is set up will impact how the virtual memory function works
· Both logically and physically
· The width (number of signal lines) dictates the addressable physical memory
· However, a disk may be only one or a small range of addresses on the physical bus
· The memory mapper, whether implemented in software or as hardware manages the mapping

Anonymous Mapping ­ Example program
· Specifying MAP_ANONYMOUS instead of MAP_SHARED results in virtual memory-only file, fd is ignored and there is no matching on-disk file
· The allocated file contents are initialized to zero (0)
· When munmap() is called, all the changes are lost

Memory Mapping Summary
· Memory mapping with the support of virtual memory provides a nice logical perspective on the memory space of the system
· Helps make programs more portable as you don't have to know the actual physical address of a memory object
· "Abstracts away" the underlying hardware · File mapping allows file data to be manipulated in RAM (virtual
memory) which is fast, and when/if needed the file can be saved to disk · Also allows sharing of file structures between processes
