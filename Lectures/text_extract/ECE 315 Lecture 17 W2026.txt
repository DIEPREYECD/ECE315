Learning Objectives
• Explain the purpose and structure of the Serial Peripheral Interface (SPI) protocol.
• Describe how SPI is used for communication between microcontrollers and
  peripheral devices.
• Interpret SPI signals (SCK, MISO, MOSI, CS) using waveform visualization tools

• Understand how to use tools like Wokwi to prove a design before committing to
  hardware, and why this is a good approach
• Appreciate the limits of using simulation/emulation compared to actual hardware
• Appreciate how having requirements aids in the design process

Why this example and why Wokwi?

• SPI, I2C, and UART are the most common serial protocols you will
  find in an embedded environment
• Sensors, actuators, and simple input/output devices (switches,
  joysticks, potentiometers, encoders) are all down in the embedded
  space
• Need to know how to look at the signals to be sure things are working
  as design
• Plus… we will have assignments that are based on Wokwi
• It’s a great prototyping environment(!)

System Requirements

• Used for “slow” sensors, like temperature
• Sample rate up to 10 samples per second
• High temporal latency and high jitter can be tolerated
   • What quantifies both?
• Factory calibration is all that is needed
   • What does that mean?
• SPI is the preferred interface

                                                               7
ADC Requirements

• 16-bit SPI interface (16-bit word data)
• 14-bit resolution
• ADC samples are in the least significant bits of the 16-bit word

 Some Assumptions…

• Choose RP2040 as the most practical, cost-effective embedded
  processor
• Over specify the temperature measurement resolution
• Assume an ideal temperature sensor
  • Doesn’t change with age, is linear in temperature, is inexpensive, is analogue, etc.
• For other reasons, an RTOS is needed
  • Could implement the RP2040 code as bare metal, but won’t
• Only functional and performance requirements matter at this point

adc-315.chip.c
• The chip initialization
   • Allocates storage for the chip state
   • Initializes the A_IN and nCS pins
   • Set the nCS pin to be watched for
     both rising and falling edge events
   • Defines the SPI configuration and
     initializes it
• Note that chip_pin_change is a
  function reference; i.e., a callback
  function that is called when the
  nCS pin state changes

                                            24
adc-315.chip.c

• The callback,
  chip_pin_change, starts
  the SPI read response
  • That is, it outputs on
    MISO the 16 bits in the
    spi_buffer
  • When complete, it calls
    chip_spi_done, which
    loads into the buffer the
    next 14-bit sample
