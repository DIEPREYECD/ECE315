Serial Peripheral Interface (SPI)

• Is an ad hoc, de facto standard synchronous serial communication
  protocol
• First proposed by Motorola in the late 1980s
• SPI became, and is, a popular low-cost interface used by embedded
  systems to communicate with each other and with peripherals
• SPI has a simple controller-peripheral architecture in which the SPI
  Controller and SPI Peripheral(s) communicate over only four wires
  • There are variants that will be discussed as needed

Old vs New Protocol Descriptions

• SPI originally was described in terms of a “Master-Slave” architecture
  • The “Master” controlled the interface, chose when it was active
  • The “Slave” responded to the Master’s initiations
  • The Slave could request interaction, but was not guaranteed to get it
Problematic historical associations
• The phrase directly references slavery, oppression, and subjugation
• Many professionals and organizations consider it unnecessarily
  evocative of traumatic history, especially when neutral technical
  terms are available

Alternatives

• The terms are often historically inherited but not essential
• More precise alternatives exist; for example,
   • primary/replica,
   • leader/follower,
   • controller/worker, controller/peripheral, central/peripheral,
   • manager/agent, etc.
• Replacement terms often describe the relationship more accurately
  and reduce ambiguity
• We’ll use Main and Subnode or Controller and Peripheral

SPI Data Transfer – Logical Shift Register
• Data is transferred by the Controller shifting data out on SDO
• Data from the Peripheral is shifted into the Controller, which will
  ignore it if it is only writing to the Peripheral
   • Controller sends 8 bits to receive 8 bits from Peripheral
   • The SDO signal is always driven by the controller
   • SDI is driven only when peripheral is selected; otherwise, SDI is tri-stated

 Daisy Chain Topology - Data Propagation
• Data is propagated from
  one subnode to the next
• The number of clock cycles
  required to transmit data is
  proportional to the subnode
  position in the daisy chain.
• In an 8-bit system, 24 clock
  pulses are required for the
  data to be available on the
  3rd subnode, compared to
  only eight clock pulses in
  regular SPI mode.

 SPI Signaling – Non-Standard L

• Not an actual standard; chip makers can implement in one of four ways
• Controller can select the clock polarity (CPOL) and clock phase (CPHA).
• CPOL bit sets the polarity of the clock signal during the idle state
  • Idle state is defined as the period when CS is high and transitioning to low at the
    start of the transmission and when CS is low and transitioning to high at the end
    of the transmission
  • CPOL = 0 (1) SCK starts off at the low (high) voltage
• CPHA bit selects the clock phase
  • CPHA = 0 (1) sample data on the first (second) SCK edge
