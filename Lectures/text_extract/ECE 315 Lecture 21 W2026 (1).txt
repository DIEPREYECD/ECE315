Memory-mapped Systems

There are three kinds of memory-mapped systems of general interest
• File Mapping
  • Make a file appear to be all in virtual memory
  • Read-only (RO) or Read-Write (RW)
• Anonymous Mapping
  • Supports extended “RAM” storage for operating systems
  • Makes the system appear to have more RAM that it physically has
• Device mapping
  • Treat peripherals as addressable entities

 Programmer’s perspective

 There are three kinds of memory-mapped systems of general interest
 • File Mapping – OSes; Linux, Windows, OSX, etc.
     • Make a file appear to be all in virtual memory
     • Read-only (RO) or Read-Write (RW)
 • Anonymous Mapping – OSes; Linux, Windows, OSX, etc.

     • Makes the system appear to have more RAM that it physically has

Memory Mapping
• Modern computers (mainframes, laptops, desktops, etc.)
  have a virtual memory that is not physically present
• Consider an N-bit processor




                                                                                                Logical address space, 2N-1
                                                                                                                              Physical RAM
  • If N=32, then 232-1 = 4GB, which could easily be all RAM
  • If N=64, then 264-1 = 17,179,869,164GB; no way that
    can be all RAM
• Instead, we can extend the available RAM “virtually”
  with another form of storage, often a disk (HD, SSD)                                                                        Disk Storage
• A mmap() function or device will “map” the extended
  space to bytes on the secondary (disk) storage

What does this have to do with interfacing?

• How the computer bus is set up will
  impact how the virtual memory
  function works
  • Both logically and physically
• The width (number of signal lines) dictates the addressable physical
  memory
• However, a disk may be only one or a small range of addresses on
  the physical bus
• The memory mapper, whether implemented in software or as
  hardware manages the mapping

File Mapping – Example program
General approach
1. Start
2. Initialize the size of the file and mapping.
3. If the file not exists, create file; Open the file.
4. If exists, truncate the file to the desired size.
5. Create a memory-mapped region.
6. Initialize memory-mapped region with some data.
7. Read and print the contents of the memory mapped region.
8. Un-map the memory and close the file.
9. Stop

Memory Mapping Summary

• Memory mapping with the support of virtual memory provides a nice
  logical perspective on the memory space of the system
• Helps make programs more portable as you don’t have to know the
  actual physical address of a memory object
• “Abstracts away” the underlying hardware
• File mapping allows file data to be manipulated in RAM (virtual
  memory) which is fast, and when/if needed the file can be saved to
  disk
• Also allows sharing of file structures between processes
