Foreground-Background Systems
• Simplest is one thread executing in a single non-preemptive loop
  • In C, just main( )
• Can manage soft- or non-real-time needs ➔ background processing
• Latency and variability of response can be high, maybe too high…
• Interrupt service routines (ISRs) provide fast response to critical
  events ➔ foreground processing
• Breaks out of main loop to do time-critical processing

• These systems are common in applications that are “human speed”

Sleep Mode with Interrupts

• Especially for power-sensitive applications, keeping the processing in
  sleep state as much as possible is a benefit
• Usually this precludes real-time response to events, but modern
  architecture has “smart peripherals” on the processor chip that can
  execute simple state machines and, if necessary, wake the processor
  up

One Non-preemptive Loop (no interrupts)
• Aka static non-preemptive scheduling
• Input sources/devices polled, possibly at different rates, in single
  loop
• The longest possible execution time of the routines possible inside
  the loop must be shorter than the loop period
  • Loop period dictates the overall worst case latency
  • Variability of the inner loop routine execution times, standalone and
    combined, dictates the overall variability
• Loop timing best defined by a hardware timer (not software)
• A final waiting sub-loop at the end of the loop uses up the remaining
  time each iteration

One Non-preemptive Loop (interrupts)

• Add a few interrupts to previous scheme
  • Ensures physical signal-triggered events are serviced deterministically
• Each interrupt service routine (ISR) must be short
  • If longer processing is needed, have ISR set things up, then do in main loop
  • E.g., set a flag to indicate that more processing is needed
• Keep the processor lightly or moderately loaded so ISRs don’t impact
  too much the main loop timing

Multiple non-preemptive loops with interrupts
• Create two or more loops so that tempos of operation can be
  different
   • E.g., gather all short time events into one loop, longer time events in another
• Think of it as tailoring for event durations
• Must still be single thread – loops run inside one outer loop
• Otherwise very similar to single non-preemptive loop
   • Each interrupt service routine (ISR) must be short
   • Keep the processor lightly or moderately loaded so ISRs don’t impact too
     much the main loop timing
• Result is (possibly) more deterministic performance

Harmonic Loop Periods
• Instead, ensure that each inner loop is harmonic wrt time
• That is, each loop’s duration is a multiple of some common time
  interval
• Ex 1: The loop periods 10 ms, 50 ms & 200 ms are harmonic.
  • Note that 50 = 5 x 10, 200 = 20 x 10, and 200 = 4 x 50.
• Ex 2: The loop periods 10 ms, 25 ms and 133 ms are not harmonic.
  • (Note: 10 ms, 20 ms and 120 ms are harmonic).
• A single hardware timer should be responsible for producing the
  timing of all of the harmonic loop periods.

                                                Adapted from ECE 315 W2025 by Dr. Bruce Cockburn   20

 Why Harmonic Loop Periods?
 • Harmonic loop periods can be nested and interleaved so that there is
   a stable, predictable repeated time frame structure
 • The total time for the outermost loop within which the events in all
   shorter loops do not drift in time.
       • They are “forced” to take a fixed amount of time
 • Repeated events can be scheduled in the frame so they never drift in
   time with respect to each other; they will never conflict

Example with Two Non-preemptive Loops
      void function do_100_ms_loop() { poll_A(); poll_B(); poll_C(); }
      void function do_50_ms_loop() { poll_D(); poll_E(); }

      initialization_steps();
      enum state_type { ST0=0, ST1, ST2, ST3 } state;
      static int state = ST0; /* The 100 ms list executes first */
      static int flag = 0;
      while (1) { /* The frame duration is 100 ms */
          /* wait for ISR of the 40 Hz timer to set flag to 1 */
          while ( !flag ) {} /* wait in idling loop */
          switch ( state ) {
              case ST0: do_100ms_loop();   state = ST1; break;
              case ST1: do_50ms_loop();    state = ST2; break;
              case ST2: /* no loop here */ state = ST3; break;
              case ST3: do_50ms_loop();    state = ST0; break;
          } /* end switch */
          flag = 0; /* cleared for next iteration */
      } /* end while */
