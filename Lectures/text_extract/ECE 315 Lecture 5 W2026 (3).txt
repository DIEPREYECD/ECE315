FreeRTOS – Single-core Scheduling

• Default is a fixed-priority preemptive scheduling policy, with round-
  robin time-slicing of equal priority tasks
• ”Fixed-priority”➔ a task’s priority will never be changed except to
                    possibly boost it
• “Preemptive”➔ the highest priority tasks are always run
   • If a new, higher priority task appears, a lower priority one will be paused
   • The lower priority task is “preempted”
• “Round-Robin”➔ tasks of the same priority take turns running

FreeRTOS – Single-core Scheduling

• Default is a fixed-priority preemptive scheduling policy, with round-
  robin time-slicing of equal priority tasks

• ”Time Sliced”➔ scheduler switches between tasks of the same
  priority each “tick interrupt”

• ”Tick Interrupt”➔ a periodic interrupt used by the RTOS to measure
  time

 Potential Issue

 • A fixed-priority, preemptive scheduler runs the risk that a high priority
   task “starves” lower priority tasks if it never ends
     • Or never enters a “Blocked” or “Suspended” state – we will look at that soon
 • One solution is to create tasks that are event-driven
     • When the tasks reaches the point where something needs to happen (an
       event), it can (should) choose to Block itself, relinquish the CPU resource
     • When the event happens, the task is unblocked and resumes
        • This may result in another task being preempted
     • While the higher priority task is blocked, lower priority tasks may run


                                 https://www.freertos.org/Documentation/02-Kernel/02-Kernel-features/01-Tasks-and-co-routines/04-Task-scheduling   15




This is one example of a resource not being given up and impacting all other
processes. A mechanism to prevent this or get around it is needed.

Producer-Consumer
• In real-time programming, the producer-consumer pattern is a
  concurrency design pattern used to coordinate two or more tasks (or
  threads) that operate at different rates — one producing data and
  another consuming it — while maintaining deterministic timing and
  avoiding data loss or race conditions.

Producer-Consumer

The producer-consumer pattern (also called the bounded-buffer
problem) is a synchronization model where:

• The producer generates data items (e.g., sensor readings, messages,
  or computation results).
• The consumer processes or uses those data items (e.g., logging,
  control output, or further computation).
• A shared buffer (queue) is used to temporarily store produced data
  until the consumer is ready to process it.

Design Pattern

• A proven template or method for solving a class of
  problems
• Common in programming
  1. Reusable – A pattern provides a solution that can be
     applied to multiple software projects.
  2. Language-independent – It describes relationships
     and interactions between objects or components, not specific syntax.
  3. Proven – It’s derived from experience and has been tested
     by many developers over time.
                                                                    Gang of Four(!)
  4. Structured – Usually includes a name, the problem it solves,
     the context in which it applies, and the solution’s structure.
