Basic Architecture
• Read-only Memory (ROM)
   • Manufacturer-specific program
     and data to support the processor’s
     operations, e.g,. specialized embedded devices like analogue-to-digital converters
• GPIO – General Purpose Input/Output
   • Typically control logic levels (signal) on external pins
• SRAM – Static Random Access Memory
   • low-power RAM with fast access
• UART – Universal Asynchronous Receiver-Transmitter
   • Supports serial data communications (send bits on one wire, receive on another)
• Timer – Can generate events based on programmed time intervals
• Watchdog – Used to monitor the processor or peripherals to make sure they are alive

What is an Operating System (OS)?

An OS is software that manages system resources for one or more
applications. It takes care of
1. Process Management – Creates, schedules, and terminates processes (running
   programs)
2. Memory Management – Allocates and tracks the use of system memory
3. File System Management – Organizes and controls access to stored data
4. Device Management – Coordinates input/output devices (e.g., keyboard, printer,
   network)
5. Security and Access Control – Protects system resources from unauthorized
   use.

What is OS? Cont’d

In the case of personal computers, tablets, smartphone, servers, and
other similar systems, an OS
• Mediates, or acts as an intermediary between users and the hardware,
• Mediates between computer systems that are networked

• In the case of an embedded system, there is usually no user, just other
  systems, and the OS’s role is substantially different

Batch OS

• Similar jobs are collected together and executed as a batch, one after
  another.
• Users prepare their jobs (programs, input data, etc.) and submit them
  to the computer operator.
• The OS then processes these jobs sequentially or according to a
  scheduling order, without manual intervention between them.
• Users do not interact with programs while they run
• Results are returned by the operator to the user when the job
  completes

Time-sharing OS

• An OS that enables concurrent access to a single computer by
  dividing CPU time into small intervals called time slices.
• Each active user or process gets a short share of CPU time in turn.
• Users perceive sole use of the computer
• User programs execute in a series of short time intervals, often
  called slices
• Slices are short enough that users perceive fast responses
  • Humans are way slower than computers
  • A computer can get a lot done in 10 ms… can you?

                                                       Made with help from ChatGPT   28

Distributed OS

• An OS that coordinates and controls multiple interconnected
  computers (nodes) in a network so they work together as one
  system.
• Each computer runs its own local OS, but the distributed OS manages
  communication, resource sharing, and task distribution across all
  machines.
• Users perceive the system as a single computer
• Big advantage is that is scales; more computers can be added to add
  capability without a perceived different in operation

Embedded OS

• An OS specifically optimized to manage hardware and software
  resources of an embedded computer system.
• It runs on devices that perform specific tasks, often with limited
  memory, processing power, and energy.
• Unlike general-purpose operating systems (like Windows or Linux
  desktops), an embedded OS is lightweight, efficient, and tailored for a
  particular application or device.
• Can be hard- or soft-real time
• Usually no user interface when deployed

Real-Time OS

• In general, an embedded operating system that can meet timing
  constraints
• Runs multiple programs (aka processes) seemingly concurrently
• It manages hardware resources and executes tasks within strict time
  constraints, ensuring that important operations occur at precise and
  predictable times

Real-Time OS cont’d

• Deterministic response: Guarantees that tasks complete within a
  fixed time
• Task prioritization: High-priority tasks preempt lower-priority ones
• Minimal latency: Very short time between event occurrence and
  response
• Multitasking support: Can run multiple tasks simultaneously with
  precise scheduling
• Reliability and stability: Designed to run continuously without failure

Scheduling Basics

Common algorithms:
• First Come, First Served (FCFS)
  • A non-preemptive scheduling algorithm where the CPU is assigned to
    processes in the order they arrive in the ready queue
  • A process runs to completion before another starts – sequential execution
• Round Robin (RR)
  • Each process in the ready queue is given the CPU for a fixed amount of time
    (called a time quantum or time slice)
  • If a process does not finish within its time quantum, it is preempted (paused)
    and placed at the end of the ready queue, allowing the next process to run

Scheduling Basics cont’d
• Priority Scheduling
   • OS assigns a priority number to each process, and the CPU executes
     processes based on their priority level rather than arrival time
   • A higher priority process is executed before a lower priority one.
   • If two processes have the same priority, they are usually scheduled using First
     Come First Served (FCFS) order.
   • This algorithm can be either preemptive or non-preemptive.
• Multilevel Queues
   • Two or more task queues that have their own scheduling method are set up
   • A queue is selected using a meta-level scheduling approach and then allowed
     to manage its tasks
